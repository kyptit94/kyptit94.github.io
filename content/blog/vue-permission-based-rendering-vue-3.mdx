It’s common in real-world applications to restrict **UI features** based on a user’s role or permission level — like hiding a delete button from regular users, or showing admin tools only to admins.

With **Vue 3** and **Pinia**, implementing permission-based UI logic is simple, clean, and scalable.

In this post, you’ll learn how to:

- Store user roles/permissions in Pinia
- Conditionally render buttons or sections
- Use helper functions and composables
- Build a global custom directive for `v-permission`

---

## 🛠 Step 1: Store Roles or Permissions in Pinia

📁 `src/stores/useAuth.js`

```js
import { defineStore } from 'pinia';

export const useAuth = defineStore('auth', {
  state: () => ({
    user: null,
    token: null,
  }),
  getters: {
    role: (state) => state.user?.role,
    permissions: (state) => state.user?.permissions || [], // optional
    hasPermission: (state) => (perm) => state.user?.permissions?.includes(perm),
    isAdmin: (state) => state.user?.role === 'admin',
  },
  persist: true,
});
```

> `permissions` can be a list like: `['create_post', 'edit_post', 'delete_user']`

---

## 🧪 Step 2: Simple Role-Based Conditional Rendering

```vue
<script setup>
import { useAuth } from '@/stores/useAuth';
const auth = useAuth();
</script>

<template>
  <button v-if="auth.role === 'admin'">Delete User</button>
</template>
```

### ✅ OR using a getter:

```vue
<template>
  <button v-if="auth.isAdmin">Delete User</button>
</template>
```

---

## ✅ Step 3: Permission-Based Rendering Using `hasPermission()`

```vue
<template>
  <button v-if="auth.hasPermission('create_post')">New Post</button>
  <button v-if="auth.hasPermission('delete_post')">Delete Post</button>
</template>
```

---

## 🧠 Step 4: Create a Reusable `usePermission()` Composable (Optional)

📁 `src/composables/usePermission.js`

```js
import { useAuth } from '@/stores/useAuth';

export function usePermission(required) {
  const auth = useAuth();
  return auth.permissions.includes(required);
}
```

```vue
<script setup>
import { usePermission } from '@/composables/usePermission';

const canEdit = usePermission('edit_post');
</script>

<template>
  <button v-if="canEdit">Edit Post</button>
</template>
```

---

## ✨ Step 5: Create a Custom Directive `v-permission`

📁 `src/directives/permission.js`

```js
import { useAuth } from '@/stores/useAuth';

export default {
  mounted(el, binding) {
    const auth = useAuth();
    const permission = binding.value;
    if (!auth.hasPermission(permission)) {
      el.parentNode?.removeChild(el); // Remove element if unauthorized
    }
  }
};
```

Register the directive globally:

📁 `main.js`

```js
import permission from './directives/permission';
app.directive('permission', permission);
```

Use it anywhere:

```vue
<button v-permission="'delete_user'">Delete</button>
```

## 🧠 Best Practices

- 🔄 Use roles for **broad access control** (admin/editor/user)
- ✅ Use permissions for **granular control** (create/delete/edit)
- 🧩 Use `v-if`, `computed`, or a `v-permission` directive based on project scale
- 🧪 Never rely on client-side permission **alone** — always enforce on backend too
